ASSIGNMENT 6 DEVELOPMENT LOG: Fishing Game

11/3/2025
- Aesthetic goals
	1. The player should get more invested reaction-wise as the game progresses.
		- Success: the player tenses up and/or heart rate increases
		- Failure: the player is looking away from the screen during gameplay
	2. The player should not require mental preparation to play the game
		- Success: the player plays the game as a break from something more
		  mentally intensive
		- Failure: the player gets overly frustrated when they lose
- Core loop
	- The core mechanics will involve guiding a fishing line down into water past
	  fish using directional keys, and a burst mechanic that allows them to power
	  through fish in the way.
	- The core loop is as follows:
		1. Cast fishing line
		2. Avoid fish and mines
		3. Reel in line when hook collides with and grabs fish
		4. Catch more fish as line is reeled in
		5. Gain money based on quantity and type of fish caught
		6. Buy bursts with money gained from caught fish

		3. (ALTERNATE) Mine explodes when hook collides with it
		4. Player cannot collect fish as line is reeled in
	- The core loop serves the aesthetic goals by encouraging more investment from
	  the player the deeper they go without hitting anything. As they get further
	  they have more potential money to lose by missing out on all of the fish
	  above them if they hit a landmine. Since the game is not particularly
	  strategic and only has a few simple controls, relying primarily on reactions,
	  it isn't mentally overbearing.

POSTMORTEM
- I originally set out to re-create a mobile game called "Ninja Fishing" albeit with
  watered-down mechanics. I wanted players to feel locked-in on a simple, somewhat
  mindless game.
- My goals did not really change over the course of the project, I picked reasonable,
  reachable goals that I knew I would achieve by emulating that mobile game.
- I think I accomplished everything, although I could have made the game more intense
  with tougher spawn rates and more lose conditions, or even a 0.001% golden chest
  full of money.
- Most things went right, I took my time to plan out how I would implement certain aspects
  such as the camera and background following the hook down and up, the game logic of
  when certain actions could be done using an Enum for the hooks status (falling, rising, etc).
  It was nice that the random values I chose for most things (spawn rates, fish values, speed
  ranges, etc.) worked so well and I didn't have to struggle with balancing.
- The biggest issue that wasn't a bug from small coding errors was the Input Manager. I tried
  to use the legacy version that I am used to and we have been using, however the inputs
  for Xbox and Playstation controllers differ slightly (face buttons on PS are rotated 90
  degrees compared to Xbox). It was easier to learn and use the new "Input System" package.
  There was also an issue with Lists and Arrays not displaying properly when serialized in
  the editor. I looked into it and it is a bug with this specific version of Unity. I was
  able to substitute them easily in my code since I only needed 7 values (6 different fish
  and the mine).
- I wish I knew the Input Manager was not going to work so I could have more time to learn
  the new Input System.
- I learned how to use the new Input System, and I was able to apply some techniques from
  Object Oriented I never knew about before (namely Enum).
